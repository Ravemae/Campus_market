Order flow algorithm

Full lifecycle
1

Browse + add to cart

User browses vendors → opens vendor page → adds products to Zustand cart store. Validate: all items must be from the same vendor (show warning if switching vendors). Cart persists in localStorage.

2

Checkout + order creation

User selects pickup or delivery. If delivery: validate hostel name is in the HOSTELS list, room number is non-empty. POST /orders sends full cart as OrderItems. Backend creates Order + OrderItem records atomically. If delivery: creates Delivery record and adds ₦200 to total.

3

Payment

Frontend receives order_id. Initialize Paystack with amount (in kobo = total × 100), email, metadata: {order_id}. On Paystack callback: POST /payment/verify with reference. Backend calls Paystack verify API, checks amount matches order total, sets is_paid=true on order, triggers notification to vendor.

4

Vendor receives + processes

Vendor dashboard polls or receives Supabase Realtime event on new paid order. Vendor confirms → marks ready → marks delivered. Each status change: PATCH /orders/:id/status + creates Notification record for customer.

5

Real-time status updates

Customer's order page subscribes to Supabase Realtime postgres_changes on the orders table filtered by id=order_id. Status badge updates live without page refresh.

6

Post-delivery review

When order reaches "delivered" status, show "Leave a review" prompt. POST /reviews with {order_id, vendor_id, rating, comment}. Reviews are averaged per vendor and shown on vendor cards.
